# Formula 1 Data Analysis and Prediction

This project builds a reproducible Formula 1 data engineering, analysis, visualization, and prediction pipeline. It starts from historical datasets and Jolpica-F1 API data, constructs model-ready race tables, produces statistical analysis outputs and figures, trains multiple machine-learning and deep-learning models, and simulates the 2026 driver and constructor championship.

The project focuses on the full data workflow rather than a single model: data acquisition, validation, storage inspection, feature engineering, statistical analysis, visualization, model evaluation, probability calibration, points-rule mapping, Monte Carlo season simulation, and final 2026 championship prediction.

## Project Goals

The main goals are:

- Build a reproducible Formula 1 data pipeline from raw data to analysis-ready and model-ready tables.
- Analyze modern Formula 1 patterns from 2019 to 2025, while using older historical data as background context.
- Visualize driver, constructor, circuit, reliability, competitiveness, and standings trends.
- Train and compare multiple models for podium prediction, Top 10 prediction, and race-points prediction.
- Convert model outputs into realistic Formula 1 race points using the current Grand Prix scoring table.
- Use backtesting, calibration, and uncertainty simulation before making the final 2026 championship forecast.
- Predict 2026 driver and constructor championship probabilities from completed-race standings and pre-race features only.

Static historical figures intentionally exclude 2026 data. The 2026 data is used for current-season state analysis and final championship prediction.

## Data Sources

The project uses four main data sources:

- Kaggle Formula 1 datasets for historical race records and SQLite-based inspection.
- `Formula1.sqlite` for older historical background analysis.
- Jolpica-F1 Ergast-compatible API for modern Formula 1 race, qualifying, standings, driver, and constructor data.
- Project-generated processed tables for 2019-2026 modern data and 2003-2026 extended modeling data.

The processed and modeling tables keep the data pipeline reproducible. Raw race `points` are preserved for descriptive analysis, while modeling-stage points are normalized from finishing position using the current Grand Prix scoring rule.

## Pipeline Stages

### Data Collection and Validation

- `download_formula1_dataset.py` downloads external Formula 1 datasets.
- `inspect_formula1_sqlite.py` inspects the SQLite dataset schema and available historical tables.
- `download_jolpica_f1_data.py` downloads Jolpica-F1 JSON data for races, results, qualifying, standings, drivers, and constructors.
- `validate_jolpica_f1_data.py` checks whether downloaded Jolpica-F1 files match the declared API totals.

### Dataset Construction and Feature Engineering

- `build_f1_model_dataset.py` converts raw Jolpica-F1 data into modern race-level modeling tables.
- `build_f1_features.py` builds pre-race and post-qualifying features for the modern 2019-2026 data.
- `build_f1_extended_features.py` combines SQLite historical records from 2003-2017 with modern Jolpica-F1 data from 2019-2026 to increase the modeling sample size.

## Modeling Tasks

The project contains three main prediction tasks.

### Podium Prediction

The podium task predicts whether a driver finishes in the top three. It compares traditional ML, advanced boosting, stacking, and deep-learning models:

- Logistic Regression
- Random Forest
- Extra Trees
- Histogram Gradient Boosting
- CatBoost
- LightGBM
- XGBoost
- Stacking Ensemble
- Upgraded MLP
- TabNet

The evaluation uses time-based splits and 2025 backtesting, with race-level Top 3 candidate metrics and feature-importance analysis.

### Top 10 Prediction

The Top 10 task predicts whether a driver finishes in the points zone. It is used as a probability signal for race-level ranking and season simulation.

The project also includes Top 10 probability calibration. This checks whether predicted probabilities behave like real event probabilities, which is important before using them in Monte Carlo simulations.

### Race-Points Prediction

The points task predicts a driver's expected race points. The continuous predicted points are useful as a model signal, but final race and season outputs use Formula 1 rule-mapped points.

For each predicted race, drivers are ranked by model signals and mapped to:

```text
25, 18, 15, 12, 10, 8, 6, 4, 2, 1
```

Only ten drivers score points in each simulated Grand Prix.

## Formula 1 Points Rules and Modeling Scope

The modeling-stage points target is normalized from finishing position using the current Grand Prix scoring table:

```text
1st: 25
2nd: 18
3rd: 15
4th: 12
5th: 10
6th: 8
7th: 6
8th: 4
9th: 2
10th: 1
```

Modeling assumptions:

- Older historical points systems are not used as the regression target, avoiding incompatible scoring scales from earlier Formula 1 eras.
- Sprint points are outside this project scope.
- Fastest-lap bonus points are not considered.
- Each race is treated as a normal full-points Grand Prix with ten scoring positions.
- Final standings and championship simulations use `rule_mapped_points` as the primary points result.
- Continuous `predicted_points` is retained as an auxiliary expected-value signal. Final 2026 race ranking uses a race-level raw predicted-points percentile plus calibrated Top 10 probability, which reduces capped-points saturation while keeping official rule-mapped points unchanged.
- Raw historical `points` remain available for descriptive analysis and visualization.

## Final 2026 Championship Prediction

The final 2026 prediction starts from completed 2026 race results and current standings. Remaining races are predicted with pre-race models only.

The final prediction compares the top three pre-race model scenarios:

- Scenario 1: `xgboost_classifier + mlp_regressor`
- Scenario 2: `lightgbm_classifier + ridge_regression`
- Scenario 3: `hist_gradient_boosting + catboost_regressor`

Each scenario produces:

- Driver championship probabilities
- Constructor championship probabilities
- Driver projected-points uncertainty intervals
- Constructor projected-points uncertainty intervals
- Deterministic remaining-race rule-mapped points
- Race-level deterministic winner confidence from winner-runner-up score gaps
- Scenario-level champion comparison and diagnostics

The primary output uses Scenario 1, while by-model output files and figures preserve all three scenarios for robustness comparison.

### Final Prediction Inputs

The final championship prediction uses the `pre_race` feature mode because future qualifying positions and starting grids are not available before the remaining races happen.

The model inputs include:

- Driver pre-race points and rank
- Constructor pre-race points and rank
- Driver recent average points
- Driver recent average finish position
- Driver recent podium count
- Constructor recent average points
- Constructor recent podium count
- Driver and constructor history counts
- Circuit history race count
- Circuit pole-win rate
- Circuit front-three podium rate
- Circuit average position change
- Circuit large-gain rate
- Circuit non-front-row winner rate
- `driver_id`
- `constructor_id`
- `circuit_id`

This design is appropriate for a true pre-race championship forecast because it avoids using unavailable future qualifying or grid information.

Remaining-race predictions support future-feature feedback between not-yet-run races. After aligning the feedback backtest with current-season online training and fixing the zero-feedback branch so it does not create projected history rows, the selected feedback weight is `1.00`, chosen by `tune_f1_feedback_weight.py` using 2022-2025 historical backtests and average combined driver/constructor final-points MAE after Top 10 probability calibration is applied. This means projected future race results are written back into later pre-race rolling features with full weight in the official forecast.

The final models also use conservative current-season online training. Completed 2026 race rows are repeated once in the final model training set. This setting was selected by `tune_f1_current_form_boost.py`: in 2022-2025 backtests, the `online1_boost0.00` configuration improved short-history driver MAE by `14.491071`, while keeping the overall combined MAE close to the baseline. Explicit ranking-score form boosts were kept out of the official prediction because they were unstable on short-history strong-form samples.

Main limitations:

- The dataset does not include weather, practice-session pace, car upgrades, grid penalties, injuries, driver substitutions, tire allocation, or safety-car likelihood.
- Driver and constructor identifiers help the model learn historical strength patterns, but they may react slowly when a new season has a sudden competitive shift.
- Circuit-history features provide technical context such as grid importance and overtaking volatility, but they do not fully represent detailed track layout, tire degradation, temperature, or team-specific car-track compatibility.
